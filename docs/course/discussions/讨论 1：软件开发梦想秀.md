## 讨论 1：软件开发梦想秀

### 1. 项目名称

> **SimpleCADforDSH：面向 DeepSeek Harness 的智能参数化 CAD 生成检索插件**

------

### 2. 项目简介

SimpleCADforDSH 是一个运行在 DeepSeek Harness 中的智能 CAD 插件。用户通过自然语言，图片或草图，描述零件需求；系统理解尺寸、孔位、结构特征和约束条件，结合企业已有 CAD 资产进行检索与复用，自动生成**可编辑、可验证、可导出**的参数化 CAD 模型。

------

### 3. 核心用户

| 用户                   | 典型需求                                 | SimpleCADforDSH 提供的价值                       |
| ---------------------- | ---------------------------------------- | ---------------------------------------- |
| 机械、工业设计专业学生 | 不熟悉复杂 CAD 菜单与建模流程            | 用自然语言快速生成学习和课程设计所需零件 |
| 初级机械设计人员       | 经常画支撑板、法兰、盒体、轴套等重复零件 | 减少重复建模和尺寸修改工作               |
| 小型制造团队           | 有历史 CAD 资产但难以检索和复用          | 从企业资产库中找到类似模型和参数模板     |

------

### 4. 核心功能特点

#### A. 自然语言智能参数化 CAD 建模

用户输入样例：

> “生成一个长 120 mm、宽 80 mm、高 20 mm 的矩形支撑板，中间开一个直径 10 mm 的通孔，四角倒圆角。”

系统把这段话转为结构化工程参数，例如零件类型、长宽高、孔径、孔位、倒角/圆角和尺寸约束。

再将结构化参数转换为 build123d 或 OpenCascade 的建模逻辑或者调用专用CAD生成模型，生成参数化 CAD 模型。

模型可导出，也可以在插件中直接编辑（这部分从FreeCAD中迁移一些基本功能）。

#### B. 企业 CAD 资产检索与复用

系统可以连接企业的 CAD 资产数据库，检索历史零件、参数模板、设计规范和相似结构。

例如用户输入“带四角安装孔的电机支撑板”，系统可以返回：

- 历史上相似的支撑板模型；
- 常用孔距、材料、厚度等参数；
- 可直接复用的参数化模板；
- 模型来源、版本和权限信息。

这一功能的价值在于：很多企业并不是没有 CAD 模型，而是**已有资产难以找到、难以复用、难以快速修改**。

#### C. 本地 CAD 生成模型接入

SimpleCADforDSH 设计为可插拔的生成器架构：

- 基础路径：LLM api 生成参数和建模脚本，再调用 build123d/OpenCascade；
- 增强路径：部署 CAD 专用生成模型或经过 CAD 数据微调的 LLM；

#### D. 几何 QA 与尺寸校验

系统生成模型后自动检查：

- 是否为单一实体；
- 几何是否封闭、是否存在无效实体；
- 长、宽、高、孔径等尺寸是否符合用户要求；
- STEP、STL、GLB 等文件是否能正确导出；

#### E. CAD 工作面板与交互编辑

在 DeepSeek Harness 中提供专门的 CAD 工作面板，建议展示：

- 左侧：模型文件；
- 中间：三维模型渲染；
- 右侧：参数表、模型树、检索结果、QA 报告；
- 底部：重新生成、导出 STEP/GLB/STL、版本保存等操作。
- 顶部：基本的FreeCAD功能

------

### 5. 项目创新点

1. **自然语言到可编辑的参数化 CAD。**
2. **生成、检索、编辑、QA 和导出闭环。**
3. **企业 CAD 资产检索与 AI 建模结合。**
4. **本地 CAD 模型可插拔部署，兼顾成本、速度、隐私和国产化需求。**

------

### 6. 一期项目边界

- 不做复杂装配体自动设计；
- 不做高级曲面、复杂钣金和完整工艺仿真；
- 不替代 FreeCAD、SolidWorks 或 Autodesk 的全部功能；
- 不承诺所有自然语言描述都能直接生成工程可制造模型；
- 不在一期直接接入未经授权的真实企业敏感 CAD 数据。

### 7. 最终初步分工

| 角色 / 小组   | 人数 | 核心职责                                                     |
| ------------- | ---- | ------------------------------------------------------------ |
| 产品负责人 PO | 1 人 | 管理用户需求、编写用户故事、决定优先级、定义验收标准、验收每次迭代成果 |
| Scrum Master  | 1 人 | 组织 Scrum 活动、维护看板、协调进度、跟踪风险与阻塞、维护项目资料和交接 |
| 生成、检索组  | 2 人 | 设计并实现 text/image-to-CAD、CAD 模型检索，以及对应的 Skills 和 Tools |
| FreeCAD迁移组 | 2 人 | 筛选、重构并迁移 FreeCAD 的基础 CAD 操作能力到插件中         |
| 集成组        | 2 人 | 整合三个模块链路，负责接口、联调、测试、Debug、发布与演示稳定性 |


### 8. 项目干系人及其关注重点

#### 内部干系人

| 干系人 | 关注重点 |
|---|---|
| 产品负责人PO | 用户需求是否被准确转化为用户故事，项目边界是否清晰、不被随意突破，每次 Sprint 是否产出可演示增量，生成、检索、编辑、QA、导出闭环是否逐步成形 |
| Scrum Master | 迭代节奏是否稳定，跨组协作是否顺畅，技术风险与阻塞是否及时暴露，项目资料、交接文档是否完整 |
| 生成、检索组 | 自然语言、图片和草图能否转为结构化工程参数，生成模型是否可编辑、可验证、可导出，企业 CAD 资产检索与复用是否有效，生成器架构是否可插拔，能否接入本地 CAD 生成模型 |
| FreeCAD迁移组 | 基础编辑功能能否稳定运行在 DeepSeek Harness 中，参数表、模型树、三维渲染与用户操作是否顺畅，生成模型能否被面板正确读取、修改、回写，用户体验是否足够轻量化 |
| 集成组 | 各模块接口是否稳定、文档是否齐全，联调、测试、Debug 是否高效，端到端流程是否无断点，发布与演示环境是否稳定可复现 |

#### 外部干系人

| 干系人 | 关注重点 |
|---|---|
| 用户：使用CAD的机械及工业设计人员 | 生成模型是否准确、可编辑、参数化，能否导出 STEP/STL/GLB 并被主流 CAD 正常打开，能否检索并复用企业历史零件、参数模板、设计规范，是否减少重复建模和尺寸修改时间，是否与现有 CAD 工作流兼容，数据隐私与资产权限是否安全 |
| DeepSeek Harness平台方 | 插件是否符合平台规范，API 调用、Token 消耗、并发是否可控，是否影响平台主流程稳定性，部署、安全、兼容性是否达标 |
| 企业信息安全部门 | 用户输入的图纸参数是否可能外泄，是否支持本地化部署和国产化替代，是否接入未经授权的真实企业敏感 CAD 数据，开源库和模型许可是否合规 |
| 可能的反对者 | AI的引入是否会影响工作者的工作地位 |
| 资助方 | 项目创新点是否有充分的商业价值，项目边界是否务实、可实现，项目组是否有充足经验和资质，项目管理体系是否成熟 |
| 未来的项目维护者 | 代码是否模块化、注释清晰，依赖版本是否锁定，架构是否可插拔、可替换，部署和运维文档是否完整 |

#### 干系人分析

| 象限 | 干系人 | 应对策略 |
|---|---|---|
| 高影响、高利益 | PO、资助方、DeepSeek Harness 平台方 | 早期介入、定期汇报、共同决策，确保期望与边界一致 |
| 高影响、低利益 | 企业信息安全部门、部分平台运维 | 按规范提交材料，避免合规与资源问题 |
| 低影响、高利益 | 最终用户、生成检索组、FreeCAD 迁移组、集成组、Scrum Master | 通过 Sprint 评审、站会、演示获取反馈，保持参与感 |
| 低影响、低利益 | 未来维护者、开源社区 | 通过文档、依赖锁定、许可说明降低后期风险 |
