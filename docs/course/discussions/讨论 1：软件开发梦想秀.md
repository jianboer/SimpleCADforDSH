## 讨论 1：软件开发梦想秀

### 1. 项目名称

> **SimpleCADforDSH：面向 DeepSeek Harness 的智能参数化 CAD 生成检索插件**

------

### 2. 项目简介

SimpleCADforDSH 是一个运行在 DeepSeek Harness 中的智能 CAD 插件。用户通过自然语言，图片或草图，描述零件需求；系统理解尺寸、孔位、结构特征和约束条件，结合企业已有 CAD 资产进行检索与复用，自动生成**可编辑、可验证、可导出**的参数化 CAD 模型。

------

### 3. 核心用户

| 用户                   | 典型需求                                 | SimpleCADforDSH 提供的价值               |
| ---------------------- | ---------------------------------------- | ---------------------------------------- |
| 机械、工业设计专业学生 | 不熟悉复杂 CAD 菜单与建模流程            | 用自然语言快速生成学习和课程设计所需零件 |
| 初级机械设计人员       | 经常画支撑板、法兰、盒体、轴套等重复零件 | 减少重复建模和尺寸修改工作               |
| 小型制造团队           | 有历史 CAD 资产但难以检索和复用          | 从企业资产库中找到类似模型和参数模板     |

------

### 4. 核心功能特点

#### A. 自然语言/单多视角Image智能参数化 CAD 建模

用户输入样例：

> “生成一个长 120 mm、宽 80 mm、高 20 mm 的矩形支撑板，中间开一个直径 10 mm 的通孔，四角倒圆角。”

系统把这段话转为结构化工程参数，例如零件类型、长宽高、孔径、孔位、倒角/圆角和尺寸约束。

再将结构化参数转换为 build123d 或 OpenCascade 的建模逻辑或者调用专用CAD生成模型，生成参数化 CAD 模型。

模型可导出，也可以在插件中直接编辑（这部分从FreeCAD中迁移一些基本功能）。

#### B. 自然语言/单多视角Image企业 CAD 资产检索复用

系统可以连接企业的 CAD 资产数据库，检索历史零件、参数模板、设计规范和相似结构。

例如用户输入“带四角安装孔的电机支撑板”，系统可以返回：

- 历史上相似的支撑板模型；
- 常用孔距、材料、厚度等参数；
- 可直接复用的参数化模板；
- 模型来源、版本和权限信息。

这一功能的价值在于：很多企业并不是没有 CAD 模型，而是**已有资产难以找到、难以复用、难以快速修改**。

#### C. 本地 CAD 生成模型接入

SimpleCADforDSH 设计为可插拔的生成器架构：

- 基础路径：LLM api 生成参数和建模脚本，再调用 build123d/OpenCascade；
- 增强路径：部署 CAD 专用生成模型或经过 CAD 数据微调的 LLM；

#### D. 几何 QA 与尺寸校验

系统生成模型后自动检查：

- 是否为单一实体；
- 几何是否封闭、是否存在无效实体；
- 长、宽、高、孔径等尺寸是否符合用户要求；
- STEP、STL、GLB 等文件是否能正确导出；

#### E. CAD 工作面板与交互编辑

在 DeepSeek Harness 中提供专门的 CAD 工作面板，建议展示：

- 左侧：模型文件；
- 中间：三维模型渲染；
- 右侧：参数表、模型树、检索结果、QA 报告；
- 底部：重新生成、导出 STEP/GLB/STL、版本保存等操作。
- 顶部：基本的FreeCAD功能

------

### 5. 项目创新点

1. **自然语言到可编辑的参数化 CAD。**
2. **生成、检索、编辑、QA 和导出闭环。**
3. **企业 CAD 资产检索与 AI 建模结合。**
4. **本地 CAD 模型可插拔部署，兼顾成本、速度、隐私和国产化需求。**

------

### 6. 项目目标

#### 6.1 目标基线

**总目标：** 在课程周期内，以仓库现有 demo 为基线，交付可重复演示的“文本/图像生成、文本/图像检索—几何 QA—参数重建—文件导出”闭环。

#### 6.2 建议的可验收目标

以下指标是项目验收设计，不代表仓库当前已经全部达成；启动迭代 2 前由 PO 与课程评审方确认最终口径。

| 编号 | 目标结果                         | 验收指标                                                     | 优先级 |
| ---- | -------------------------------- | ------------------------------------------------------------ | ------ |
| G1   | 文本/单多视角image生成可编辑零件 | 固定提示词，覆盖支撑板、法兰、盒体、轴套； QA 通过；STEP 可由 FreeCAD 打开；支持修改长、宽、高、孔径并重建；完成 STEP、STL、GLB 导出 | 必须   |
| G2   | 文本/单多视角image检索           |                                                              | 必须   |
| G3   | QA 结果可见且可复现              | 每次生成返回通过或失败原因；能区分非单一实体、几何不封闭、尺寸不符；面板显示报告 | 必须   |
| G4   | 面板具备有限编辑能力             | 开工前锁定FreeCAD迁移清单，逐条定义面板操作、模型回写和验证方法；只验收清单内能力 | 必须   |
| G5   | 端到端演示可恢复                 | 固定剧本完整跑通                                             | 必须   |

#### 6.3 迭代安排与收缩规则

| 迭代 | 主要结果                 | 阶段关口                          |
| ---- | ------------------------ | --------------------------------- |
| 1    | 完成 G1、G2、G3          | 样例达到 G1/G2/G3 的验收证据要求  |
| 2    | 按清单推进 G4            | FreeCAD基础功能成功迁移           |
| 3    | 完成总演示和归档，完成G5 | 按 G5 剧本完整跑通，PO 确认遗留项 |

### 7. 最终初步分工

| 角色 / 小组   | 人数 | 核心职责                                                     |

| 产品负责人 PO | 1 人 | 管理用户需求、编写用户故事、决定优先级、定义验收标准、验收每次迭代成果 |
| Scrum Master  | 1 人 | 组织 Scrum 活动、维护看板、协调进度、跟踪风险与阻塞、维护项目资料和交接 |
| 生成、检索组  | 2 人 | 设计并实现 text/image-to-CAD生成、CAD 模型检索，以及对应的 Skills 和 Tools |
| FreeCAD迁移组 | 2 人 | 筛选、重构并迁移 FreeCAD 的基础 CAD 操作能力到插件中         |
| 集成组        | 2 人 | 整合三个模块链路，负责接口、联调、测试、Debug、发布与演示稳定性 |

### 9. 项目章程

本章程规定 SimpleCADforDSH 的交付边界、决策机制和验收依据。

#### 9.1 章程基线

| 要素       | 约定                                                         |
| ---------- | ------------------------------------------------------------ |
| 项目目的   | 在课程周期内实现 SimpleCADforDSH 的可用闭环：文本/图像到参数化CAD生成及检索、几何 QA、参数重建及编辑和文件导出 |
| 开发基线   | GitHub 仓库现有 DeepSeek Harness 插件 demo 及其 text-to-CAD、build123d、QA、同窗口面板和导出链路 |
| 交付优先级 | G1、G2、G3、G4、G5 为必须项                                  |
| 计划周期   | 3个迭代                                                      |
| 决策边界   | PO 决定范围、优先级和验收；Scrum Master 负责过程与阻塞；各组在确认范围内实现；集成组统筹联调和演示 |

#### 9.2 假设、约束与依赖

| 类别     | 约定与确认方式                                               |
| -------- | ------------------------------------------------------------ |
| 假设     | 现有 demo 可复现；build123d、Python、FreeCAD 及文件交换链路可用；提示词和课程零件数据可按期准备 |
| 约束     | 只验收简单单一实体；G3 不超过 6 条迁移项；敏感数据；范围变更须 PO 确认 |
| 平台依赖 | DeepSeek Harness 可加载插件，模型服务和调用额度满足联调、演示；集成组统筹验证 |
| 环境依赖 | Node.js、TypeScript、python、build123d（待定）、FreeCAD 和开源CAD多模态生成检索模型 |
| 数据依赖 | 开源CAD数据集，如ABC等                                       |

#### 9.3 主要风险

| 风险/触发信号                                          | 影响              | 责任                |
| ------------------------------------------------------ | ----------------- | ------------------- |
| 固定样例生成/检索、 QA 通过率不足、QA 失败原因不可区分 | G1/G2/G3 不能达标 | 生成、检索组负责    |
| FreeCAD功能、工具菜单迁移失败                          | G4不达标          | FreeCAD迁移组负责   |
| 平台、模型、环境或导出链路不稳定                       | G5 演示中断       | 集成组负责          |
| 新需求或增强功能挤占必须项                             | 范围失控          | PO/Scrum Master负责 |

#### 9.4 治理、变更与资料

- 每个迭代结束进行阶段关口评审，检查可演示成果、验证记录、未完成项和风险；继续推进或收缩范围由 PO 确认。
- 范围变更遵循“提出—评估影响—PO 确认—更新文档/看板—执行并验证”。变更记录至少包含原因、涉及目标、工期/接口影响和验收变化。
- 课程资料统一归档到 `docs/course/`；接口文档、演示清单和验证记录注明代码版本、环境版本、样例编号、预期与实际结果及问题状态。
- AI 只提供信息处理、方案生成和风险提示；范围取舍、质量权衡、伦理边界和最终验收由人负责并留痕。
