
# 讨论5：风险管理最佳实践

## 迭代一风险

### 李健博：

| 风险                             | 风险描述                                                     |
| -------------------------------- | ------------------------------------------------------------ |
| 风险一：GPU 显存不足             | 开发环境 GPU 显存有限，运行生成模型时可能出现显存溢出，影响调试和开发效率。 |
| 风险二：多视角图像生成算法不成熟 | 现有科研工作中，多视角图像生成 CAD 的相关算法尚不成熟，视角间几何一致性与信息融合等问题仍有待解决，可能缺乏可直接复用的成熟方案，增加算法选型与开发难度。 |
| 风险三：Skill 与 Tools 编写困难  | 对 DSH 插件的 Skill、Tools 编写规范及调用机制不够熟悉，可能导致工具接口设计、参数传递和功能集成耗时较长。 |


### 刘子轩：
| 风险                                           | 风险描述                                                     |
| -------------------------------- | ------------------------------------------------------------ |
| 风险四：生成尺寸与用户输入不一致           |依赖自然语言或图像解析出长、宽、厚、孔径等工程参数，再由建模脚本生成模型。若大模型参数提取偏差、单位换算错误或建模脚本映射不准，可能出现尺寸偏差超过验收要求等问题，影响生成结果与后续编辑。 |
| 风险五：图像输入质量参差不齐 |用户上传图像时，若图片模糊、光照不均或缺少比例尺，会导致单/多视角生成与检索的识别准确率明显下降。 |
| 风险六：检索资产库样例数据不足       | 若资产库样例模型、标签、来源和版本数据准备不足，将难以覆盖相似度排序、名称差异召回和空结果等验收场景。 |

### 常诚：
| 风险                                           | 风险描述                                                     |
| -------------------------------- | ------------------------------------------------------------ |
| 风险七：开发、集成与验收环境不一致           |GPU 环境、FreeCAD/Python API 版本、开源模型权重和 DSH 插件运行环境在成员本地与集成环境之间可能存在差异，出现本地可运行、集成后推理失败或建模接口报错；环境差异会拉长 US01—US04、US14、US23 等任务的联调与验收周期。 |
| 风险八：验收样例与正反例数据准备不足 |迭代一大量验收依赖具体样例：清晰与模糊图片、同一零件多视角和不同零件混合输入等图像样例和大量反例。若样例准备滞后或覆盖不全，AT01—AT23 中的异常与边界用例难以执行，容易出现验收阶段集中返工。 |
| 风险九：团队对 CAD 内核操作与参数化建模调试经验不足       | 合法性检查和符合性检查等任务，需要正确完成选边映射、参数校验、失败保护和结果核对。成员若对 CAD 内核行为、拓扑变化和参数化重建链路不熟悉，异常场景排查会明显耗时。 |

### 严翊航：

| 风险                                 | 风险描述                                                     |
| ------------------------------------ | ------------------------------------------------------------ |
| 风险十：模块间接口与数据格式不一致   | 生成、检索、详情展示与 QA 由不同成员并行开发，若模型标识、字段命名、单位、返回结构和错误码等接口约定不统一，联调时容易产生字段缺失、类型不匹配或单位错位，导致 US04、US08—US12 的集成回归反复返工。 |
| 风险十一：大模型推理服务限流或不可用 | 文本/图像生成与检索依赖大模型 API 或本地推理服务，若出现调用额度不足、限流或服务超时，生成与检索主流程会中断，影响 US01—US07 的开发进度、联调与验收。 |
| 风险十二：迭代一联调与演示准备时间不足 | 迭代一仅两天，需并行完成生成、检索、QA 的联调、回归和证据整理；若高优先级故事挤压集成窗口，端到端固定剧本和环境样例在评审时不稳定，将影响 G1—G3 的阶段验收与演示。 |

### 侯永森：

| 风险                                 | 风险描述                                                     |
| ------------------------------------ | ------------------------------------------------------------ |
| 风险十三：多模态生成不可控风险   | 文本/图像/多视角输入可能缺尺寸、尺寸冲突或尺度错误；生成模型可能与参数面板不一致，影响后续编辑。 |
| 风险十四：检索与元数据风险 | 检索可能漏检、空结果处理不当或新旧输入结果残留；溯源、规格、版本信息可能缺失或展示异常，影响资产复用判断。 |
| 风险十五：质量检查规则风险 | 几何合法性检查可能漏判非单一实体或开口几何；尺寸检查需正确执行默认公差、单独公差覆盖及超差报告，否则会误放行或误拦截。 |

### 许祖嘉：

| 风险                                 | 风险描述                                                     |
| ------------------------------------ | ------------------------------------------------------------ |
| 风险十六：关键人员容量饱和导致依赖任务阻塞 | 迭代一中常诚、刘子轩的任务估算均已达到每人 12 小时有效容量，且生成、检索组承担 50 个故事点。若 US01、US02 或 US05 的缺陷修复超出估算，后续参数展示、多图生成与检索以及 QA 联调可能被连带阻塞；团队剩余的 6 小时分散在其他成员，未必能直接补足关键人员缺口。 |
| 风险十七：阶段核验暴露能力缺口引发范围膨胀 | I1-GATE-T1、I1-GATE-T2 依赖现有 STEP 兼容和参数重建能力。若核验时发现现有能力不足，可能需要临时增加补齐任务，甚至提前引入迭代二 G4 编辑或迭代三 G5 导出的完整功能，挤占首迭代 US01–US12 的交付容量；PO 若未及时评估影响并确认变更，容易造成范围失控。 |
| 风险十八：故事验收与阶段验收混淆导致完成状态误判 | 首迭代既要满足 US01–US12 的全部验收用例，也要核验 G1–G3 的阶段要求。若 I1-REG-T1 汇总时只依据核心回归或演示结果，遗漏四类零件、STEP 打开、参数重建等阶段证据，PO 在 I1-PO-T2 中可能将部分通过误记为全部完成，导致实际完成点数及后续迭代计划失真。 |

### 庞佳泽：

| 风险                                 | 风险描述                                                     |
| ------------------------------------ | ------------------------------------------------------------ |
| 风险十九：生成脚本执行安全与异常回滚不足 | LLM 生成的建模脚本会在本地直接执行，可能出现死循环、非法参数（孔径大于板宽、倒角超过相邻边）或语法错误；若缺少统一的参数预校验、执行超时保护和失败回滚重试，US01–US05 的生成成功率不稳定，调试与返工成本高。 |
| 风险二十：开源模型代码与权重获取、许可及版本锁定风险 | 单/多视角图像生成与检索依赖开源模型代码和权重，若外网受限、源仓库或权重地址变更、版本未锁定，部署推理无法复现，会直接卡住 US01–US07 的联调与验收；同时需确认开源许可能否用于课程演示。 |
| 风险二十一：样例提示词与回归基线未固化，修复后难判断退化 | 验收依赖固定提示词、固定 QA 判定和 AT 用例，若提示词版本、建模脚本版本和通过率基线没有入库固化，缺陷修复后难以区分「改进」还是「退化」，验收前回归容易反复。 |
