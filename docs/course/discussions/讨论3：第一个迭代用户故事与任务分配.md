# 讨论3：第一个迭代用户故事与任务分配

## 1. 编制依据

本计划明确首个迭代的故事范围、任务分工、交付物和验收安排，编制依据如下：

- [讨论 1：软件开发梦想秀](讨论%201：软件开发梦想秀.md)的 G1–G3、两天迭代安排、正式组别及成员职责。
- [讨论 2：编写用户故事及其验收测试标准](讨论2：编写用户故事及其验收测试标准.md)的故事编号、目标映射和验收测试标准。
- [各组用户故事估算与优先级](讨论3：各组用户故事估算与优先级.md)中三个小组提交的故事点、优先级及理由。
- 现有演示系统的文本生成、参数展示及部分 QA 能力，重点安排功能完善、联调与验收。

各组提供故事估算与优先级，许祖嘉（PO）负责范围汇总、任务分配与验收安排，李健博（Scrum Master）依据任务清单编制 WBS 和 WBS 字典。

正式组别及成员沿用讨论一：生成、检索组（常诚、刘子轩）、FreeCAD 迁移组（侯永森、庞佳泽）、集成组（余智皓、严翊航）。

## 2. 首迭代目标、范围与容量

### 2.1 目标及范围

首迭代为开发期第 1–2 天，以讨论一的 G1–G3 为阶段目标，形成可演示的文本／图像生成、CAD 资产检索、参数及模型信息展示、几何与尺寸 QA 流程。

| 目标 | 首迭代故事 | 对应结果 |
| ---- | ---------- | -------- |
| G1 | US01–US04 | 文本、单视角和多视角生成；查看生成模型的可编辑参数 |
| G2 | US05–US10 | 文本、单图和多图检索；查看来源、规格和版本 |
| G3 | US11–US12 | 几何合法性检查；关键尺寸与公差符合性检查 |

US13–US22（G4）安排至迭代二，US23–US25（G5）安排至迭代三，均不计入首迭代范围和故事点。

AT11-04 使用现有编辑能力准备模型状态样例。参数重建与 STEP 兼容性按第 2.3 节核验，不提前纳入 G4、G5 的完整故事交付。

### 2.2 容量及估算口径

按每个工作日 8 小时计，六名开发成员两天共 96 人时。每人预留 4 小时用于会议、评审、回顾与协调，有效任务容量为每人 12 小时、合计 72 小时，包含开发、自测、联调和证据整理。PO 与 Scrum Master 的管理工作单列。

故事点沿用各组估算，仅用于相对复杂度比较，不换算工时。任务工时依据现有系统的剩余工作量估算，由主责人在启动会复核；实际完成点数作为后续速度参考。

### 2.3 阶段验收与故事验收衔接

首迭代完成文本、单视角及多视角 CAD 生成和检索，不将图像生成或图像检索推迟至后续迭代。故事验收依据讨论二，阶段验收依据讨论一；两类验收分别记录。

| 目标 | 讨论一阶段要求 | 首迭代核验安排 |
| ---- | -------------- | -------------- |
| G1 | 支撑板、法兰、盒体、轴套生成，QA 通过，STEP 可由 FreeCAD 打开，支持关键参数修改与重建 | 执行 US01–US04，补充盒体、轴套固定样例；利用现有能力核验 STEP 兼容及参数重建，分别归档证据 |
| G2 | 文本、单／多视角检索，返回 Top-K 相似模型及参数模板，展示来源、版本和关键尺寸，结果可加载或用于再编辑 | 执行 US05–US10，在联调中验证排序、模板返回与结果加载；首迭代采用加载至面板的复用路径 |
| G3 | 每次生成显示 QA 结论或失败原因，区分非单一实体、不封闭及尺寸不符 | 执行 US11–US12，验证各生成入口的报告可见性与当前模型状态一致性 |

G1 的参数重建和 STEP 兼容核验不替代迭代二的 G4 编辑功能开发、迭代三的 G5 导出与总演示验收。现有能力不足时，记录具体缺口，由 PO 评估补齐任务及容量；涉及目标或迭代边界调整时按讨论一变更流程确认。阶段要求未全部满足时，不将 G1–G3 标记为全部完成。

生成、检索组承担 50 点，集成组承担 8 点。FreeCAD 迁移组参与测试资产准备、输入校验和验收测试，不改变故事所属组。

### 3.1 执行与交接顺序

- 生成、检索组高优先级顺序为 US01 → US05 → US02 → US04，中优先级为 US06 → US03 → US07，较低优先级为 US08 → US09 → US10。可并行准备数据，但功能验收须满足依赖。
- US04 在模型及参数可用后验证；US11、US12 与生成主流程并行准备正反例和报告接口，在可用模型交接后完成联调。
- 生成依赖链为 US01／US02／US03 → US04 及 US11／US12；检索依赖链为 US05 → US06 → US07 → US08／US09／US10。详情界面可先用固定测试数据开发，最终必须验证真实检索结果。
- 中午交接内容包括模型标识与当前状态、图片组及替换规则、检索结果与元数据、目标尺寸与公差、QA 报告结论及失败明细。生成、检索组和集成组共同确认，李健博记录。
- 几何 QA 与尺寸 QA 分别展示结果；同一模型同时存在几何与尺寸问题时不以其中一项通过掩盖另一项失败。

## 5. 完成定义与验收证据

故事完成须满足：讨论二对应的**全部**验收用例执行并达到预期；真实输入和当前模型结果可复核；异常和边界场景有明确提示；自测、交接及集成验证完成；阻断性问题已处理；PO 核对证据并作出验收结论。G1–G3 阶段完成还须满足第 2.3 节要求。核心回归只作复查，不替代全部验收用例。

记录至少包括版本／环境、用例编号、样例、操作、预期与实际结果、通过／失败状态、执行人及截图或日志。生成结果的复现指结构、尺寸、公差和状态满足同一验收标准，不要求每次生成的脚本或文件逐字一致。尺寸报告记录目标值、实测值、绝对偏差和采用的公差；指定公差优先于默认 0.2 mm，偏差等于公差时视为符合要求。

缺少比例尺或实际尺寸时须提示补充信息，不得将像素尺寸直接作为 CAD 实际尺寸。
